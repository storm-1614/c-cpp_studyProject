# 串口通信

> 衔接 [51 单片机基本结构和工作原理](../../2-51单片机的基本结构和工作原理/readme.md) 中的 **SFR、P3 口第二功能、SP、DPTR**。这里先学 **查询式串口收发**，不引入中断、缓冲队列或复杂协议。
>
> **示例前提**：经典 12T 8051/AT89C52 兼容串口、**11.0592 MHz** 晶振、**9600 baud、8N1**、Keil C51 + `REG52.H`。这些条件不是所有“51 单片机”都通用的默认值。

## 1. SFR 之间是什么关系？

前面已经知道 P3 口具有第二功能：**P3.0/RXD 接收，P3.1/TXD 发送**。单片机用 **特殊功能寄存器（SFR）** 配置和操作这些硬件。

| 寄存器 / 位 | 作用 | 在本实验中做什么 |
| --- | --- | --- |
| `SCON` | 串口控制与状态；含 `SM0/SM1`、`REN`、`TI`、`RI` 等 | 选择模式 1、允许接收、查看收发标志 |
| `SBUF` | 串口数据缓冲；**写入是发送，读取是接收**（硬件内部为不同缓冲） | CPU 与串口之间交换一个字节 |
| `TMOD` | 定时器工作模式 | 将定时器 1 设置为模式 2（8 位自动重装） |
| `TH1` / `TL1` | 定时器 1 重装值 / 计数值 | 配合晶振产生所需溢出频率 |
| `TCON.TR1` | 定时器 1 运行控制位 | 启动定时器 1 |
| `PCON.SMOD` | 经典 8051 中的波特率倍增控制位 | 本例清零，使用正常倍频系数 |
| `IE.ES` / `IE.ET1` | 串口 / 定时器 1 中断允许位 | 本例均关闭，采用查询方式 |
| `P3.0` / `P3.1` | 复用引脚 RXD / TXD | 连接外部串口设备 |

简化关系：

```text
晶振时钟 ──> 定时器1（TMOD、TH1/TL1、TR1）──> 串口波特率
                    PCON.SMOD ───────────┘
CPU <──读/写 SBUF──> 串口硬件（SCON 控制，TI/RI 状态）
                                       ├── P3.0 / RXD
                                       └── P3.1 / TXD
```

**与之前笔记的区别**：`SP` 是栈指针，`DPTR` 是 16 位数据指针；它们都不是串口收发数据的寄存器。本例不需要主动配置它们。**并非所有 SFR 都能按位寻址**，例如 `SBUF` 使用字节读写，`PCON.SMOD` 在示例中通过对 `PCON` 做掩码操作来设置。

## 2. 初始化顺序

本例使用 **串口模式 1**：1 位起始位、8 位数据位、1 位停止位，即常说的 **8N1**（无校验）。

1. 不使用中断：关闭串口中断 `ES` 和定时器 1 中断 `ET1`，先停止定时器 1（`TR1 = 0`）。
2. 设置 `SMOD = 0`，使波特率不倍增。
3. 设置 `TMOD` 中定时器 1 的位为模式 2（保留定时器 0 的配置）。
4. 设定 `TH1 = TL1 = 0xFD`，对应**指定的晶振和 12T 时序**。
5. 设置 `SCON = 0x50`：`SM0=0`、`SM1=1`（模式 1）、`REN=1`（允许接收），并清 `TI/RI`。
6. 设置 `TR1 = 1`，开始产生波特率。

为什么选 `0xFD`？经典 **12T** 内核、Timer1 模式 2、串口模式 1 下：

```text
baud = (2^SMOD / 32) * fosc / (12 * (256 - TH1))

SMOD=0, fosc=11,059,200 Hz, TH1=0xFD=253:
baud = 11,059,200 / (32 * 12 * 3) = 9,600
```

换用 12 MHz 晶振、1T/6T 内核或独立波特率发生器时，**不能直接套用这组重装值**。

## 3. 发送和接收流程

**发送（TXD）**

`SBUF = value` → 串口硬件逐位发送 → `TI = 1` → 程序发现 `TI` → 软件清 `TI = 0` → 可以继续发送下一字节。

**接收（RXD）**

外部数据到达 → `REN=1` 时串口硬件接收 → `RI = 1` → 程序检查 `RI` → `value = SBUF` → 软件清 `RI = 0`。

注意：在经典模式 1 中，`TI` 是在发送**停止位开始时**置位的，不应将其误解为整个停止位已经发送完毕。`TI` 和 `RI` **不会因读取标志而自动清零**，必须由软件清除。轮询过慢可能丢失连续接收的数据，后续再学习中断和接收缓冲区。

## 4. 最小可运行框架：串口回显

示例代码：[`uart_echo.c`](./uart_echo.c)，使用 `REG52.H` 提供的**寄存器名称**，不手写未经核实的 SFR 地址。

```c
void main(void)
{
    unsigned char ch;
    uart_init();

    while (1) {
        if (uart_try_read(&ch)) {
            uart_send_byte(ch); // 收到的字节原样发回
        }
    }
}
```

这里 `uart_init()` 配置串口，`uart_try_read()` 非阻塞查询 `RI` 并读取 `SBUF`，`uart_send_byte()` 写入 `SBUF` 并等待 `TI`。

## 5. 如何验证？

- 在 **Keil C51** 中选择与目标芯片匹配的设备，编译 `uart_echo.c` 并烧录到 8051 开发板；**本文件不是 Arduino UNO 的 `.ino` 草图**。
- 使用**电平兼容的 USB-TTL 串口模块**交叉接线：开发板 `P3.1/TXD → 模块 RXD`，`P3.0/RXD ← 模块 TXD`，并连接 **GND ↔ GND**。不要直接连接传统 RS-232 电平接口。
- PC 串口工具选择正确端口，设置 **9600、8 数据位、无校验、1 停止位**；关闭工具的“本地回显”选项，避免误判。
- 发送字符 `A`，预期收到 `A`。再发送 `123`，预期收到 `123`。

如果没有回传，先核对 **晶振频率 / 1T 或 12T、TX/RX 是否交叉、共地、收发电平、PC 串口设置**，再排查代码。

## 6. 需要结合课堂或芯片资料确认

- **确切芯片型号和头文件**：课堂使用的是经典 AT89C51/AT89C52、STC 派生型号，还是其他 8051？`REG52.H` 的定义只适用于匹配的目标设备。
- **时钟与波特率来源**：实物晶振频率、1T/6T/12T 时序、Timer1 是否用作波特率发生器，以及是否存在独立波特率发生器。
- **端口和连接**：目标板串口是否确实引出 `P3.0/P3.1`，是否经过电平转换芯片；USB-TTL 模块的 IO 电平必须匹配开发板。
- **定时器占用**：本方案占用定时器 1，不能不经协调又让它为其他功能独立计时。
- **开发工具**：`uart_echo.c` 针对 Keil C51 头文件编写；如使用 SDCC、Proteus 或其他工具链，须先适配头文件与编译/仿真配置。
- **实验报告要求**：是否要求中断收发、指定波特率、发送固定字符串或波形截图，需按课堂指导书调整。

**依据**：[Philips《80C51 Family Hardware Description》](https://www.pjrc.com/tech/8051/80C51_FAM_HARDWARE_1.pdf)（串口模式、SCON、TI/RI、Timer1 波特率公式）；[AT89C52 数据手册](https://ww1.microchip.com/downloads/en/DeviceDoc/doc0313.pdf)。此材料只使用芯片资料和目标头文件支持的**符号名**，不增列绝对 SFR 地址。
